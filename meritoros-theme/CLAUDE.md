# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build Commands

```bash
# Build CSS (one-time, minified)
npx tailwindcss -i ./assets/css/tailwind.css -o ./assets/css/tailwind.build.css --minify

# Watch CSS during development
npx tailwindcss -i ./assets/css/tailwind.css -o ./assets/css/tailwind.build.css --watch
```

Tailwind scans: `./*.php`, `./template-parts/**/*.php`, `./inc/**/*.php`, `./assets/js/**/*.js`

## Architecture

### Page Structure

Every page template follows the same pattern:

```php
<?php /* Template Name: Name */ get_header(); ?>
<main class="bg-white text-slate-900 antialiased">
    <?php get_template_part('template-parts/section', 'section-name'); ?>
    <?php get_template_part('template-parts/section', 'newsletter'); ?>
</main>
<?php get_footer(); ?>
```

Pages live in `page-*.php` at the root. Each page is composed entirely of template parts from `template-parts/`. There is no block editor — all content is managed via ACF fields.

### ACF Field Access

ACF fields are registered in `inc/acf-fields.php` (the main file, ~1200 fields) and exported to `acf-json/`. Use these helpers defined in `functions.php`:

| Function | Use |
|---|---|
| `mer_field($name, $fallback)` | Get ACF field with fallback |
| `mer_esc($text)` | `nl2br(esc_html())` — use for all ACF text output |
| `mer_text($name, $fallback, $nl2br)` | Echo escaped ACF text, optional nl2br |
| `mer_img($name, $class, $alt)` | Render `<img>` from ACF image array |
| `mer_img_url($name, $fallback)` | Get URL from ACF image array |
| `mer_icon($name_field, $fallback_icon, $class)` | Render Lucide `<i>` from ACF icon name |
| `mer_sub($name, $fallback)` | Get ACF sub-field inside a loop |

**Sections shared across multiple pages** (e.g. `section-case-studies`, `section-bpo-historie`) read from the front page, not the current page:

```php
$_fp_id = (int) get_option('page_on_front');
$value  = get_field('field_name', $_fp_id);
```

**ACF Pro is not installed** — do not use Repeater, Flexible Content, or other Pro field types. Use multiple separate Group fields instead (e.g. `hist_1`, `hist_2`, `hist_3`).

### Slider Pattern

All sliders follow the pattern from `section-kariera-dlaczego.php`:

- **Title + arrows in one flex row** (heading left, prev/next right)
- Prev button: `w-12 h-12 rounded-full bg-white border border-slate-200`
- Next button: `w-12 h-12 rounded-full bg-[#48c279]` (green)
- **Peek effect**: `overflow-hidden pl-6 lg:pl-[max(24px,calc((100vw-1280px)/2+24px))]`
- **Dots generated by PHP** `foreach` below the slider, not by JS
- JS uses `querySelectorAll('#prefix-dots button')` and `getMax()` to compute max scroll position

### Tailwind — Critical Gotcha

`tailwind.build.css` is compiled from PHP/JS source files. **Classes that don't appear in scanned files will not be in the build.** This affects:

- **Contact Form 7** — CF7 form markup is stored in the database, not scanned. Any Tailwind classes used in CF7 forms must be manually added to `assets/css/style.css`.
- **Dynamically composed class strings** — avoid string concatenation like `'text-' + color`. Use full class names.

### Icons

Lucide Icons are loaded from `assets/js/lucide.min.js` (local, not CDN). Use `<i data-lucide="icon-name">` — icons are initialized via `lucide.createIcons()` in `assets/js/main.js` on `DOMContentLoaded`.

### JavaScript

`assets/js/main.js` handles: mobile menu, case studies carousel (with touch/swipe), video modal, custom dropdown, smooth anchor scroll. Page-specific slider logic is inline `<script>` at the bottom of each template part.

### Deployment

There is no CI/CD. The developer edits files locally in `Desktop/projekty/meritoros.pl/meritoros-theme/` and manually uploads changed files to the server. After adding new Tailwind classes, the CSS must be rebuilt before uploading.

### WPML

The site is multilingual (Polish primary). When reading fields on pages that may have translations:

```php
$_page_id = get_the_ID();
$_orig_id = apply_filters('wpml_object_id', $_page_id, get_post_type(), true, apply_filters('wpml_default_language', null));
$value = get_field('field_name') ?: ($_orig_id !== $_page_id ? get_field('field_name', $_orig_id) : null);
```

### Custom Post Types

- `customer-story` (slug: `historia-klienta`) — single template: `single-customer-story.php`
- `media-article` (slug: `artykul-medialny`) — single template: `single-media-article.php`

Both registered in `inc/cpt-*.php`. Fields in `inc/acf-fields-customer-story.php` and the main `inc/acf-fields.php`.
